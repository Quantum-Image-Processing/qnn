Copy-Move Forgery Detection using a
Siamese Swap-Test Quantum Neural Network

Phase-2 Progress & Evaluation Report
Final Year Project · Phase 2  |  Date: 26 July 2026  |  Pipeline: cmfd_swaptest_pipeline.py (v2)

1. Executive Summary

This report documents the current state of a quantum-machine-learning pipeline for copy-move forgery detection (CMFD) — detecting regions of an image that have been duplicated and pasted elsewhere in the same image. The system pairs a classical patch descriptor with a Siamese swap-test quantum neural network (QNN) that learns a similarity score between two image patches, followed by a spatial offset-consistency filter that keeps only genuine duplications.

Headline finding. The infrastructure (data loading, patch extraction, QNN similarity, metrics, multi-dataset evaluation) is sound and runs end-to-end. However, the model currently over-detects severely — it flags 50–97% of each test image as forged. Consequently the previously-remembered “~80%” figure was recall, not accuracy; true pixel accuracy on those samples is ~3–12%, and localization quality (F1/IoU) is low. The remaining work is detection quality, not plumbing.

2. Objective & Target Output

The intended end product: given any input image, decide whether it is forged, and if so, localize the exact duplicated region as a bounding box or heatmap. That decomposes into four capabilities, tracked in the gap analysis (§8).

3. System Architecture

The architecture is a pairwise similarity model, which is the structurally correct choice for copy-move (the task is inherently “does patch A match patch B elsewhere?”). A single-patch classifier cannot express duplication. An earlier degenerate embedding (fixed amplitude embedding + data-independent tied unitary, which the swap test provably cancels) was replaced with a data re-uploading ansatz so the tied weights have a genuine effect on the measured overlap.

ComponentSpecification
Quantum registers4 qubits per register, two registers (patch A, patch B) = 8 qubits + 1 ancilla for the swap test = 9 wires total
Trainable parameters24 — shape (2 layers × 4 qubits × 3 rotations RX/RY/RZ); the same weight tensor is tied across both registers (Siamese)
Similarity readoutSwap test: ancilla ⟨Z⟩ = |⟨ψA|ψB⟩|², a learned similarity in [0,1]
Patches32×32 px, stride 8, sliding window → 841 patches on a 256×256 image
Patch descriptor24-dim: 12 largest-magnitude DCT coefficients + 12-bin intensity histogram, L2-normalized, angle-encoded via data re-uploading
Candidate pairingO(N log N) lexicographic block-matching (Fridrich-style) — sort by feature, compare within a sliding window, instead of O(N²) all-pairs
False-match suppressionOffset-consistency vote over (dy, dx): genuine copy-move produces many pairs sharing one offset (translation only — rotation is a documented TODO)
Binary maskGT: grayscale → NEAREST resize → threshold >128. Prediction: fill matched-pair patches → morphological close (dilate→erode)
TrainingSelf-supervised synthetic copy-move pairs (parameter-shift gradients, MSE on similarity labels)

Is the architecture correct? Conceptually yes for measuring patch similarity, and the degeneracy bug is fixed. But it is incomplete as a detector: (i) there is no image-level forged/authentic decision, (ii) the DCT+histogram descriptor is not rotation/scale invariant, and (iii) it is not yet shown that the quantum similarity outperforms a classical distance on the same features (an ablation is needed).

4. Datasets & Their Roles

Training and evaluation must use different data sources — a recurring point of confusion. The Siamese similarity must be trained on synthetic pairs because real CMFD datasets provide no patch-level correspondence ground truth.

DatasetRoleWhy
Synthetic (self-supervised)Training — mandatoryOnly source of labeled positive/negative patch pairs; CoMoFoD masks have no correspondence labels
CoMoFoD (small v2)Primary evaluation (headline)Real forgeries + real binary masks; loader already matches it (5,000 forged images)
COVERAGE (100 pairs)Stress test onlyAdversarial by design (similar genuine objects); useful to prove generalization, but not a headline metric

Recommendation: train on synthetic, report on CoMoFoD. Never evaluate on synthetic data (it only proves the model learned its own augmentation). Keep COVERAGE as a “hard case” data point.

5. Evaluation Methodology — why not accuracy?

Forged regions occupy only ~2–11% of pixels, so the pixel classes are extremely imbalanced. Under this imbalance, plain accuracy is actively misleading: a model that predicts “nothing is forged” scores ~90–98% accuracy while detecting zero forgeries.

MetricDefinitionMeaning here
Accuracy(TP+TN) / allMisleading — rewards predicting nothing
RecallTP / (TP+FN)Fraction of true forged pixels found. Gamed by flagging everything → this is the “80%” trap
PrecisionTP / (TP+FP)Of the pixels flagged, how many were actually forged
F12·P·R / (P+R)Honest single scalar — collapses if precision OR recall is bad
IoU (Jaccard)TP / (TP+FP+FN)Localization overlap — directly measures “does the predicted region match the true region?”
Reporting rule for this project: lead with F1 and IoU; cite precision+recall as the pair that explains F1; never headline accuracy. IoU is literally the metric that measures the stated goal (exact forged area).

7. Key Finding — systemic over-detection

The predicted mask covers most of each image. The diagnostic signature is consistent: recall ≈ 1.0, precision near the forged-area base rate. The offset-consistency filter, which is supposed to suppress coincidental matches, barely rejects anything at loose thresholds (e.g. 9,734→7,984 pairs). On self-similar texture, false matches cluster into offset bins just like true ones, so they survive.

Two compounding causes: (1) the DCT+histogram descriptor is weak — it cannot separate a true duplicate from a genuinely similar region; (2) thresholds/resolution were not tuned for the test conditions. Tightening parameters (§6.2) confirms the mechanism is fixable — surviving false matches dropped ~95% — but precision remains low, pointing at the descriptor as the deeper bottleneck.

9. Recommendations

  • Datasets: keep training on synthetic pairs (mandatory); report headline metrics on CoMoFoD; use COVERAGE only as a stress test.
  • COVERAGE — keep it. ~142 MB extracted, the loader reads it, and a second dataset strengthens the report. Optionally delete only the 142 MB download zip (OneDrive_1_7-26-2026.zip) to reclaim space.
  • Metrics: report F1 + IoU (with precision/recall); drop accuracy from headline claims.

10. Roadmap — next steps

  1. Establish an honest baseline — run a 20–50 image CoMoFoD batch with tuned parameters and record mean F1/IoU. (Nothing trustworthy exists yet.)
  2. De-flood localization — tune sim-threshold / min-offset-votes; strengthen the offset filter (e.g. RANSAC on offsets); if precision still stalls, replace/augment the descriptor with a rotation/scale-invariant feature (e.g. Zernike moments).
  3. Add the image-level decision — derive forged/authentic from the offset-consistent matched area, calibrated on authentic images to bound false positives.
  4. Ablation — confirm the swap-test QNN beats a classical similarity on the same features; otherwise justify the quantum component explicitly.
  5. Final output format — convert the mask to a bounding box (connected components) or a similarity heatmap. Trivial, and correctly done last.
Single most important next action: steps 1–2 — get a real CoMoFoD number, then kill the over-detection. Everything else builds on that.
